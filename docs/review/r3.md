# Airy panel review: R3 (Channels)

Surface: operator tool (`@airy/ui`, sky #38bdf8 on navy, DM Sans, JetBrains Mono for ids/urls/keys).
Kit rules apply as written (mono for ids/counts/times, 24 px desktop hit-target floor, 44 px phone
floor per this brief's own Sizes line). Judged from rendered evidence only: `r3-channels.json` /
`-tree.txt` / `-1440.png` / `-375.png` / `-320.png` and their findings/annotated overlays,
`r3-rule-changed-1440.png`, `r3-added-1440.png`, `r3-remove-confirm-1440.png`,
`r3-hive-modal-1440.png`, `r3-hive-modal-375.png`, `r3-webhooks-1440.png`,
`r3-webhook-modal-1440.png`, `r3-connected-dev-1440.png`, `r3-try-1-1440.png`, `r3-try-2-1440.png`.

The owner's ask for this page ("same token, different channels, decisions per channel, pick by
name not id") is met in shape: one Hive connection card feeds every row, each row carries its own
rule, and the channel picker lists `#name · Server`, never an id (`r3-channels-tree.txt`, 192
options, none showing a raw Discord id).

## Interactions and feedback seen

Rule radio (add-form and per-row) -> fills at once, toast bottom-right with Undo
(`r3-rule-changed-1440.png`: `#airy-talk-🚧 : When it's worth it` toast, green left accent, sky
"Undo" link). Add channel -> button disabled until a channel is picked (`disabled` in
`r3-channels-tree.txt` line 202, visibly muted), new row appears at the top with the picker
cleared and a toast without Undo (`r3-added-1440.png`: `#general-1` above `#airy-talk-🚧`,
toast `Airy talks in #general-1`, no Undo, matching the brief). Remove -> confirm dialog names
the channel and explains the consequence (`r3-remove-confirm-1440.png`: "Remove #general-1?" /
"Airy stops answering there. Its rule is forgotten; you can add the channel again.", red-outline
"Remove"). Hive connect -> "Change" opens a modal with address, a key field that stays blank
("Leave empty to keep the stored key"), and an agent picker with "Find agents" instead of typing
an agent id (`r3-hive-modal-1440.png`). Try a message -> busy spinner on "Ask the Hive"
(`r3-try-1-1440.png`) then a green-accented verdict in mono, "Airy would answer `yes 100%`"
(`r3-try-2-1440.png`). Connection state -> amber "Cannot decide yet" with the reason sentence
when the key lacks `decisions.make` (`r3-channels-1440.png`), green "Decides with gemma-local"
once a fuller key is connected (`r3-connected-dev-1440.png`).

## Blocks: does the usual case need this here

Hive connection card, "Where Airy talks" (picker + rule + rows), Webhooks folded below: all three

No second navigation surface, no step wizard for a one-tap rule change: correct, matches S15/S21.

## Findings

### High

1. **The row's Pause switch is a 20 px target, under this tool's own floor** —
   `r3-channels.json` / `r3-channels-1440-legend.md` #22: `switch "Airy talks in #airy-talk-🚧"`
   measures 36x20 at 1440 (`r3-channels-1440-findings.png`, box 22), the only one of the 24
   probed targets on this page under the 24 px desktop floor this review series has used since R2.
   The brief's own Sizes line promises "phone 44 px"; the control has no wrapping LabelText in
   `r3-channels-tree.txt` (unlike the neighbouring rule radios, which do), so its hit area is
   almost certainly the same fixed 20 px tall rectangle at 375/320, where the row sits below the
   fold and is unconfirmed by screenshot. Pause is named as a frequent action in the brief. Fix:
   give the switch at least a 24 px (desktop) / 44 px (phone) hit area, e.g. a padded label like
   the rule radios already use.

### Medium

2. **Every modal's backdrop stays legible instead of suppressing the page behind it** —
   confirmed by pixel sampling across all 5 modal captures (`r3-hive-modal-1440.png`,
   `r3-hive-modal-375.png`, `r3-webhook-modal-1440.png`, `r3-try-1-1440.png`,
   `r3-try-2-1440.png`): the card background only goes from `#0F1722` to `#070B10` and the page
   background from `#050A11` to `#020508` under the scrim, a uniform ~50% darken that preserves
   the text/background contrast ratio rather than killing it. "Hive connection", "Change", "Try a
   message" and the page title all read clearly through every modal (crops in this review).
   The brief already had to fix two other Modal defects this round (ConfirmDialog contrast, duplicate
   landmarks); this one wasn't caught. Fix: raise the scrim opacity well past the point where text
   is still readable, or add a backdrop blur, so the modal is the only readable layer.

3. **The add-channel rule selector doesn't reset after a successful add** — base state
   `r3-channels-1440.png` (before any add) has the add-form's rule on "When mentioned", matching
   the brief's "rule (preselected 'When mentioned')" (crop confirms the sky ring is on "When
   mentioned"). `r3-added-1440.png`, captured right after adding `#general-1` with "When it's
   worth it" selected, still shows the add-form's rule on "When it's worth it" even though the
   channel picker itself cleared back to "Pick a channel" (crop confirms the ring moved to "When
   it's worth it" and stayed there). One half of the mini-form resets, the other doesn't: the next
   channel added without an explicit new choice silently inherits the previous rule. Fix: reset
   the rule to "When mentioned" together with the picker on every successful add.

4. **"Pick a channel" is one flat list, already at 192 options with real data** —
   `r3-channels-tree.txt` lines 7-199: a native `<select>` with 192 `#name · Server` options
   across two Discord servers, no `<optgroup>` / server header, no filter beyond native type-ahead.
   This is the control the whole page exists to deliver on ("pick a channel by name instead of
   typing an id"), and it is already at a scale (192 rows, two servers) where scanning a flat list
   stops working. Fix: group by server at minimum (`<optgroup>`), ideally a searchable combobox.

### Nit

5. **The "cannot decide yet" banner isn't tied to a specific row** — `r3-rule-changed-1440.png`
   and `r3-added-1440.png` both place the amber "The Hive cannot decide yet, so the 'When it's
   worth it' channels answer only when mentioned for now" banner directly under the add-form's own
   rule radios, not next to the row(s) it actually describes. In `r3-added-1440.png` two rows
   exist with different rules (`#general-1` on "When it's worth it", `#airy-talk-🚧` on "When
   mentioned"); nothing marks which row the banner is about. Once a bot has many rows with mixed
   rules this reads as a page-level note rather than the fact that *this specific channel* is
   quietly behaving as "when mentioned" today. Not yet confirmed against owner taste. Fix
   direction: a small per-row note on any row set to "When it's worth it" while the connection
   can't decide, in addition to or instead of the single banner.

## Measured, explained, not counted as new findings

  channel": the 16 px field-text rule is phone-only; not applicable at 1440.
- `r3-channels-1440-legend.md` #3-#21, #23-#24 (28-1070 px targets): all above the 24 px desktop
  floor this series has used since R2; not defects.
- `r3-channels-375.json` targets (3 boxes, 1x1): the radios' visually hidden native inputs; the
  wrapping tile is the real target (`LabelText ... clickable [cursor:pointer]` in
  `r3-channels-tree.txt`), confirmed not a defect.
- axe: 0 violations, 1440/375/320 (`r3-channels.json`), consistent with the brief's claim of 0
  across the other captured states; I could not independently re-run axe on the 8 non-base states
  since only the base page shipped probe/axe JSON, only screenshots for the rest.
- The boxed-off channel emoji (`#airy-talk-🚧` rendering with a tofu glyph) is the stated headless
  browser emoji-font gap, not a defect.
- The free-text "Channel name" field inside "Try a message" (`r3-try-1-1440.png`) is a hypothetical
  probe, not a real channel assignment ("// The Hive reads it as part of the message"); a picker
  isn't needed there the way it is for "Where Airy talks".
